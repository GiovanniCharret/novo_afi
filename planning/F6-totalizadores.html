04

Código-chave

Os dois pontos onde dá pra errar feio: a query agregada (perfomance + null-safety) e a integração do refresh no consumer SSE (evitar refetch em cada file_done).

backend/app/server.py — endpoint
@app.get("/api/contratos/{contrato_id}/totais")
def totais_contrato(contrato_id: str, db = Depends(get_db)):
    contrato = db.get(Contrato, contrato_id)
    if not contrato:
        raise HTTPException(404, "Contrato não encontrado")

    # Uma query só: JOIN nf_entries via upload_batches
    row = db.execute(
        select(
            func.coalesce(func.sum(NfEntry.valor_total), 0),
            func.count(func.distinct(NfEntry.numero_nf)),
        ).join(UploadFile, NfEntry.upload_file_id == UploadFile.id)
         .join(UploadBatch, UploadFile.batch_id == UploadBatch.id)
         .where(UploadBatch.contrato_id == contrato_id)
    ).one()
    soma, contagem = row

    def pct(num, den):                            # null-safe
        return None if den == 0 else float(num) / float(den)

    return {
        "contrato_id": contrato.id,
        "numero": contrato.numero,
        "valor_contrato": contrato.valor_contrato,
        "valor_cde": contrato.valor_cde,
        "soma_nfs_enviadas": soma,
        "pct_enviado_sobre_contrato": pct(soma, contrato.valor_contrato),
        "pct_enviado_sobre_cde": pct(soma, contrato.valor_cde),
        "total_nfs_no_banco": contagem,
    }
frontend/src/App.jsx — gatilho de refresh
// dentro do reader.read() loop do SSE consumer:
if (evt.type === "batch_done") {
  setIsUploading(false);
  // dispara refresh do card; não bloqueia outras UI updates
  totalizadoresRef.current?.reload();
}

// TotalizadoresCard expõe reload via useImperativeHandle:
const TotalizadoresCard = forwardRef((props, ref) => {
  const [data, setData] = useState(null);
  const load = useCallback(async () => {
    const r = await fetch(
      `/api/contratos/${props.contratoId}/totais`,
      { credentials: "same-origin" }
    );
    if (r.ok) setData(await r.json());
  }, [props.contratoId]);

  useEffect(() => { load(); }, [load]);
  useImperativeHandle(ref, () => ({ reload: load }), [load]);
  // ... render barras + foot
});
05

Riscos & mitigações

Risco
Sev
Mitigação
Divisão por zero quando valor_contrato = 0 (acontece — ~30 contratos da base têm valor zero).
HIGH
Helper pct(num, den) retorna None se denominador zero; frontend renderiza variante "Valor contratual não definido" sem barras (mock B).
Refresh a cada file_done derruba o backend em batches de 550 PDFs — seria ~550 queries durante o upload.
MED
Refetch só em batch_done (1 query no fim) ou ao montar. Nunca em file_done. Decisão documentada no PR.
COUNT(DISTINCT numero_nf) conta NFs duplicadas como uma só — mas a UNIQUE em business_key já garante isso a nível de linha; o DISTINCT é defesa em profundidade.
LOW
Mantido. Custo é desprezível (~110 contratos × milhares de NFs no pior caso) e o intent fica claro na query.
SOMA vai contar NFs de batches pré-F2 (contrato_id IS NULL) sob o contrato errado se alguém forçar o id.
LOW
Filtro é WHERE upload_batches.contrato_id = :id — batches sem contrato não casam. Adicionar teste explícito do caso pré-F2.
06

Perguntas abertas

Mostrar progresso por tranche dentro do mesmo contrato?
Hoje o card é por contrato. Alguns contratos têm múltiplas tranches (ex.: ECFS 327/2013 — 1ª Tranche, mas há ECFS 283/2010 — 4ª Tranche da mesma sigla). Spec atual trata cada (sigla, tranche) como contrato distinto na base — ok manter. Mas se aparecer pedido de "soma por sigla", precisamos de outro endpoint.
Decidir com · usuários, antes da Fase B
Formato visual do "% da CDE": absoluto ou relativo ao contrato?
Mock A mostra R$ 980k de R$ 1,7M (80% do contrato) — dois valores na mesma barra. Alternativa: barra simples, sem a parenteses do "80% do contrato". O 80% vem de participacao_cde e é fixo por contrato — não muda com uploads.
