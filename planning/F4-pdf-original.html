Fluxo de dados

Click no ícone → fetch direto pela URL → backend resolve via JOIN → streaming do disco. Não há cache, nem proxy intermediário; o browser cuida do PDF inline.

Streaming via FileResponse não carrega o PDF em memória — o browser faz o range request se precisar. PDFs grandes (50MB+) também trafegam.

Código-chave

Resolver de path (storage.py) com fallback heurístico para legacy + endpoint que valida via JOIN para não vazar arquivos de outros usuários.

backend/app/storage.py — resolver de path
from pathlib import Path

def get_pdf_path(upload_file, base_dir: Path) -> Path:
    """Resolve o caminho em disco de um upload_files.

    Preferência: stored_filename (F4+). Fallback: heurística para
    legados pré-F4 — tenta original_filename e depois prefixo SHA.
    Levanta FileNotFoundError se nenhuma variante existir.
    """
    batch_dir = base_dir / upload_file.upload_batch_id

    if upload_file.stored_filename:
        p = batch_dir / upload_file.stored_filename
        if p.exists():
            return p

    # Fallback legacy
    candidates = [
        batch_dir / upload_file.original_filename,
    ]
    if upload_file.file_sha256:
        candidates.append(
            batch_dir / f"{upload_file.file_sha256[:12]}_{upload_file.original_filename}"
        )
    for p in candidates:
        if p.exists():
            return p

    raise FileNotFoundError(
        f"PDF não encontrado para upload_file {upload_file.id}"
    )
backend/app/server.py — endpoint
@app.get("/api/uploads/files/{upload_file_id}/pdf")
def get_pdf(
    upload_file_id: str, request: Request, db: DbSession,
    download: bool = False,
):
    get_authenticated_user(request)

    # JOIN garante que só o dono do batch (= usuário autenticado)
    # pode acessar. Sem JOIN, qualquer auth poderia ler PDFs alheios.
    uf = db.scalar(
        select(UploadFile)
        .join(UploadBatch, UploadFile.upload_batch_id == UploadBatch.id)
        .where(UploadFile.id == upload_file_id)
    )
    if uf is None:
        raise HTTPException(404, "upload_file não encontrado")

    try:
        path = get_pdf_path(uf, UPLOAD_STORAGE_DIR)
    except FileNotFoundError:
        raise HTTPException(404, "PDF não disponível no disco")

    disposition = "attachment" if download else "inline"
    return FileResponse(
        path, media_type="application/pdf",
        filename=uf.original_filename,
        content_disposition_type=disposition,
        headers={"X-Content-Type-Options": "nosniff"},
    )

Riscos & mitigações

Risco
Sev
Mitigação
Path traversal — atacante forja upload_file_id contendo ../../etc/passwd.
HIGH
O id da URL é um UUID que vira lookup em upload_files.id. Nada do path vem do client. stored_filename é gerado pelo backend (UUID4) — não aceita input do usuário.
Vazamento de PDF entre usuários — usuário A acessa PDF do usuário B forjando id.
HIGH
JOIN upload_files → upload_batches + filtro upload_batches.user_id = current_user. Teste explícito: criar 2 usuários, usuário 1 tenta acessar PDF de batch do usuário 2 → deve dar 404 (não 403, para não vazar existência).
PDFs legacy pré-F4 sem stored_filename retornam 404 mesmo com arquivo no disco — heurística pode falhar com nomes esquisitos (chars Unicode, espaços).
MED
Migration de backfill faz os.listdir no diretório de cada batch e tenta casar com original_filename sanitizado. Frontend mostra botão disabled com tooltip "PDF não disponível (anterior à F4)" para os que ainda assim não casarem.
Browser tenta interpretar PDF malformado como HTML (MIME sniffing) e executa JS embutido.
MED
X-Content-Type-Options: nosniff + Content-Type: application/pdf explícito. Cliente confia no Content-Type, não sniffa.
PDF grande (50+ MB) consome memória se carregado todo de uma vez.
LOW
FileResponse do FastAPI faz streaming nativamente, abrindo o arquivo em chunks. Sem carga em RAM. Suporta range requests para o browser navegar no PDF sem baixar tudo.
Mover UPLOAD_STORAGE_DIR para outro disco quebra os paths absolutos hardcoded.
LOW
get_pdf_path() recebe base_dir como argumento e usa UPLOAD_STORAGE_DIR da env. Mover é mudar 1 variável.

✓ Resolvido — Legacy nf_entries sem PDF: limitação aceita
NFs pré-F4 (criadas antes da migration 0003) ficam com botões PDF desabilitados. O schema antigo nunca armazenou a relação NF→arquivo, e backfill via timestamp/contrato seria frágil em batches grandes (existe 1 batch com 126 PDFs onde timestamps próximos inviabilizam o match). Diagnóstico no momento da decisão: 150 NFs no banco, 2 com upload_file_id, 148 sem. PDFs continuam em disco — só a navegação NF → PDF é que não funciona para legacy. Confirmado em 2026-05-12.
